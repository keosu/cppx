# 核心接口契约与迁移说明

更新日期：2026-10-11。适用于本次 R01–R09 核心正确性修复。现有命名模块、xmake 接入方式及 `ok/err` 调用形式保持不变；公共类型的内部布局已变化，库和消费者必须一起重新编译，不承诺旧 BMI/IFC 或二进制 ABI 兼容。

## 错误处理（R01）

`cppx::expected<T, E>` 以 `std::expected<T, E>` 存储值或错误，支持 `T == E`、只能移动的值/错误，以及没有默认构造函数的 `E`。复制、赋值和移动的可用性及异常规范由成员类型决定，不再将可能抛异常的移动声明为无条件 `noexcept`。`value()`/`error()` 在状态不匹配时继续抛 `std::runtime_error`。

`map` 支持返回 `void`；`expected<void, E>` 新增 `value`、`map`、`map_err` 和 `and_then`。左值链式操作保留原结果、复制需要传播的错误；右值操作移动值/错误。传入 `std::ref` 可显式保留引用；结果本身遵守 `std::expected` 的值类型限制，不存储引用。同一结果对象的修改需要调用方同步。

## JSON（R02、R03）

- 分别存储 `int64_t`、`uint64_t` 和有限 `double`。`get_type()` 对三种存储仍返回 `type::number`；`is_integer()` 指有符号整数存储，`is_unsigned()` 指无符号整数存储。非负整数文本解析为无符号存储，负整数文本为有符号存储。
- 整数应使用 `as_int64()`、`as_uint64()`、`as_integer<T>()`、`as<T>()` 或相应 `serializer<T>`。这些接口检查目标范围，并拒绝小数转整数。`as_number()` 仍返回 `double`，显式调用它转换大整数时可能舍入。
- 拒绝 NaN、无穷、超出整数存储范围的整数文本，以及超出 `double` 可表示范围的浮点文本。浮点输出保留浮点语法，例如 `1.0`，并支持有限 `double` 的往返与负零。
- 输入和输出字符串均按 UTF-8 验证；支持中文、emoji、全部 JSON 控制字符转义和 UTF-16 代理对，拒绝孤立代理项、过长 UTF-8 编码、非法码点及不完整字节序列。`std::string` 内的 NUL 可以通过转义往返。
- 严格检查前导零、小数/指数、控制字符、转义、逗号和尾部输入。只允许 JSON 的四种空白字符。重复对象键直接报错，不再覆盖早先的值。
- 默认解析上限为 **16 MiB 输入、128 层容器**。可传 `json_parse_options{max_input_bytes, max_depth}` 调整，深度上限最高为 512；深度 0 只允许标量。语法/范围/资源错误使用 `json_parse_error`，`position()` 返回从 0 开始的字节位置。程序构建的 JSON 输出也限制深度，`dump` 缩进参数限 `-1..1024`。
- 数组下标检查越界。整数 map 键必须完整解析、符合目标范围，转换后重复的键也报错。`save_json`/`load_json` 检查文件读写错误；`load_json` 先读取文件，解析上限不是整个文件加载过程的内存预算。

```cpp
auto value = cppx::json::parse("18446744073709551615");
auto integer = value.as_uint64(); // 精确保留 UINT64_MAX
auto limited = cppx::json::parse("[[1]]", {1024, 8});
```

原先接受非法 JSON、截断小数、损失整数精度或覆盖重复键的调用现在会失败。结构体宏仍允许缺失字段保留默认值；它不是 schema 校验器。JSON 对象的并发修改需要外部同步。

## 时间与定时器（R04、R05）

`parse_iso8601` 接受 `YYYY-MM-DDTHH:MM:SS[.1至9位小数](Z|+HH:MM|-HH:MM)`。时区必填，严格检查日期、时间和完整输入；不接受闰秒。解析按 UTC 计算，与本地时区和 DST 无关，小数截断到 `system_clock` 的分辨率。`format_iso8601`/`format_rfc3339` 输出 UTC，向下截断至毫秒，也支持 epoch 之前的时刻。超出系统时钟范围的时间返回错误；整数时间戳构造的缩放溢出抛 `std::out_of_range`。

`parse_time`/`format_time` 使用本地时间。解析启用 DST 推断，拒绝被 `mktime` 归一化的非法日期和 DST 跳时空洞；DST 回拨产生的歧义由平台 C 运行库选择一个合法偏移，需精确指定偏移时使用 ISO 接口。格式 `string_view` 会复制为 NUL 结尾字符串，嵌入 NUL 被拒绝。格式化采用平台可重入时间函数并检查输出，输出最多 64 KiB；失败抛异常。进程级 `TZ`/locale 变更仍需应用统一协调。

定时器的周期回调首次立即执行，一次性回调在延迟后执行。周期必须大于 0，延迟可为 0；空回调、负延迟及无法表示的超长等待被拒绝。

- 外部 `stop()` 可重复调用，唤醒等待并等待已经开始的回调结束；它无法中断用户回调内部的阻塞操作。
- 回调内 `stop()` 只请求停止，不会 join 自己；回调内重启同一定时器抛 `std::logic_error`。
- 一次性回调完成后 `is_running()` 自动变为 false。回调异常使定时器停止，可通过 `exception()` 或 `rethrow_if_failed()` 获取；下一次启动清除旧异常。
- 生命周期状态有同步。工作线程先持有共享状态，再调用用户函数；支持回调内销毁定时器，随后只保留工作线程自己的状态直到回调返回。销毁后不得再访问定时器。对象析构与其他外部调用仍需调用方协调。
- `scope_timer` 的析构回调为尽力执行，异常不会从析构传播；需要处理回调错误时，应在回调内捕获并记录。`scope_timer`/`stopwatch` 不提供同一对象的并发修改保证。

## 并行算法、线程池和队列（R05、R06）

`parallel_for`、`parallel_for_each`、`parallel_invoke` 在返回或抛异常前 join 所有已经启动的线程。工作回调的首个已记录异常传回调用线程；其余工作可能继续执行。线程创建/回调对象构造在部分启动后失败也会先清理已启动线程。调用方须同步共享数据，容器并行遍历期间不得修改结构。

`thread_pool(threads, capacity = 0)` 的容量指等待队列，0 表示不设上限；正在执行的任务不计入容量。默认行为兼容原来的无界队列。

- `submit` 对已关闭或已满的队列抛异常；`submit_for(timeout, fn, args...)` 可等待队列空间，关闭会唤醒等待者。任务和参数按值拥有、在执行时移动，需要引用时传 `std::ref`。
- 工作异常保存在返回的 `future` 中。工作线程向同一线程池提交子任务时直接内联执行，支持单线程池内提交后立即 `get()`；这会改变子任务的调度顺序和调用栈深度。
- `close()` 拒绝新任务，并排空已接受的任务；可以在工作线程调用。`shutdown()` 关闭并 join，可以重复或由多个外部线程调用。工作线程中调用 `shutdown()` 会抛异常。
- **线程池必须由工作线程之外的拥有者析构**；任务不能销毁自己的线程池。关闭不取消已接受任务，析构/关闭的等待时间取决于用户任务能否结束。不同线程池之间或用户自己构造的 future 等待环仍需要应用避免。

`channel` 的关闭唤醒读者与写者，拒绝新发送，已有内容继续接收直到空；容量 0 表示无界。新增 `send_for(value, timeout)` 与 `receive_for(timeout)`。发送返回 false 表示超时或关闭；接收的 nullopt 表示超时或关闭且已排空，可通过 `is_closed()` 查询当时的状态。元素移动/复制异常会传播；对会抛移动异常的元素，不能保证队首值完全未改变。

`blocking_queue::push` 现在返回 bool；旧代码可以忽略返回值，关闭后的调用应检查它。`wait_pop()` 返回 optional，`pop_for()` 支持超时；旧 `pop()` 在关闭并排空后抛异常。所有队列须先关闭、让使用它的线程结束，再析构。`atomic_counter` 的增减采用定义明确的整数回绕。

## 文件和日志（R07、R08）

临时文件通过 C++23 `noreplace` 排他创建，临时目录根据 `create_directory` 的实际创建结果取得所有权；名称碰撞最多重试 128 次。随机生成器按线程隔离，名称不是安全令牌。前缀只能是文件名组件；新增第二个参数可指定父目录，内部保存绝对路径。创建/关闭失败抛异常，不把已有文件或目录当作自己的资源。

移动转移所有权，移动赋值先清理原资源；`keep()` 释放清理责任并保留 `path()`，与原来清空路径的行为不同。析构清理不抛异常；若必须确认删除成功，应显式调用删除接口并处理结果。对象持有期间，调用方不得替换其路径指向的资源；这不是针对恶意共享目录替换攻击的句柄级沙箱。

普通文件接口检查文件大小、短读、读失败以及写入后的 flush/close，错误通过 `expected` 返回。文本接口仍使用平台文本模式；二进制接口保留字节。读取不是并发修改文件的事务快照。

`write_file_atomic(path, content)` 以二进制方式写入同目录排他临时文件，检查完成后进行替换；失败会清理暂存文件并报告错误。Windows 使用同卷替换，其他平台使用 rename，原子可见性取决于文件系统；不承诺掉电持久性，不保留旧文件全部元数据。

日志级别使用原子访问，sink 配置和写入有锁保护；时间戳使用可重入转换。文件打开、写入、轮转和显式 `flush()` 的失败抛异常。轮转按实际字节数判断，保留当前文件及 `.1` 至 `.4`；单条超大日志完整保存，`max_size = 0` 关闭轮转。一个路径应只由一个 logger 管理，未提供跨 logger 或跨进程轮转协调。

应显式调用 `flush()` 来确认写入成功，析构不是可观察的 I/O 错误通道。移除文件 sink 会将它脱离 logger，再检查 flush；即使失败也可以重新配置。`log_scope` 的析构不传播异常，失败记录在所属 logger 的 `last_error()` 中。普通日志操作的异常仍直接返回调用方。

## CLI 与数学（R09）

长短选项统一验证定义与 choices，支持 `--name=value` 和 `--` 终止选项，未知选项不再被接受。重复名称/别名、保留的 help 名称和无效定义抛异常。负数可作为选项值；与已有选项名称冲突的值用 `--name=值` 传入。最后一次重复选项生效，短选项不支持组合形式。

解析 `--help`/`-h` 成功返回带 `help_requested()` 的结果，**库不打印也不退出进程**。子命令帮助文本随结果返回；位于 `--` 之后的 help 是普通位置参数。调用方需要迁移：

```cpp
auto result = parser.parse(argc, argv);
if (!result) {
  std::cerr << result.error().message() << '\n';
  return 1;
}
if (result.value().help_requested()) {
  std::cout << result.value().help_text();
  return 0;
}
// 在这里使用解析后的业务参数。
```

数学函数避免先做可能溢出的整数中间运算。整数 sum/product、向量加减乘、缩放、点积和数值跨度遇到目标类型溢出时抛 `std::overflow_error`；整数最小值的绝对值也报告溢出。整数 range 使用更宽的步进中间值，median 使用安全中点，magnitude 使用 hypot。mean 避免简单累加溢出；mean/median 拒绝非有限输入。空统计输入、非法随机分布参数、非法 clamp 范围有显式检查。返回 double 的统计/插值不是任意精度运算，极大整数转换和浮点结果仍受 double 精度与范围限制。空 product 保留原来的 0 语义。

## 验证范围

`tests/test_core_contract.cpp` 使用独立条件检查与进程退出码，不依赖被测库自己的测试断言。修复前的初始用例复现 30 项失败，修复后通过；后续增加编译期类型约束、数字/编码语料、DST、并发关闭、资源归属和日志轮转用例。异步等待设置明确期限，超时直接使测试进程失败。

本轮不把通过率称为覆盖率。操作系统级线程创建资源耗尽、真实磁盘满/短读故障注入、TSan/ASan/UBSan、持续 fuzz、24 小时压力运行及 Linux/macOS 的动态验证仍属于后续验证工作。当前证据、构建模式及消费者报告见 [开发状态](STATUS.md)。

## 2026-10-12 接口共存修复

同时导入 `cppx.serialization` 与 `cppx.file_system` 时，两参数 `cppx::write_file(path, text)` 现在唯一匹配文件系统 API，并返回 `expected<void, error_info>`。序列化内部的 `read_file/write_file` 辅助函数已移入 `json_detail`；依赖旧辅助函数的调用应迁移到 `read_file_text/write_file` 或 `load_json/save_json`。这项变更修复了升级演练中实际发现的编译歧义，消费者回归同时导入全部模块进行检查。
